# 2026-11-02: Astra's audit and exact-pruning search

This follow-up was led by **Astra (OpenAI Codex)** at the owner's request.
Astra directed the audit, synthesized the completeness argument, and developed
the exact-pruning direction. Sol carried out implementation and independent
code reviews; Argon supplied an independent mathematical review. The original
binary/hex digit-family classification is Rick Regan's prior work, not a new
claim of this audit. The owner supplied the project and the RTX 4090 run time.

## The enumeration survived the audit

The initial question was whether the orbit construction could have omitted a
family. It did not: the two palindrome conditions are equality constraints on
bits. Their connected components are precisely the free choices, subject to
zero padding and the leading one bit. Every valid number gives one assignment,
and every permitted assignment gives a valid binary/hex palindrome.

The four allowed digit alphabets provide a second construction. Independent
small enumerations and exact count formulas agreed with the orbit generator.
The audit confirmed this existing foundation rather than replacing it.

## A real implementation bug needed a fresh check

The GPU launched as many as `2^38` candidates while counting survivors in a
32-bit integer. An `all`-mode group with `2^33` survivors could wrap its count
to zero, bypass the buffer-overflow check, and still be credited as visited.
Consequently, planned-versus-visited totals alone could not certify coverage.

The repair widens the entire count path to 64 bits. A regression against the
actual kernel reproduced the old failure: eight increments starting at
`2^32 - 4` returned 4 rather than 4,294,967,300 and overwrote buffer sentinels.
The fixed code passes. Small survivor buffers also force repeated splits while
preserving exactly the independently enumerated candidate set.

This bug did not show that a triple palindrome had been lost in the published
normal searches. It showed that their overflow guarantee needed repair and
their large GPU-dependent ranges needed revalidation. The fresh results and
comparison with the original run are recorded in [RESULTS.md](RESULTS.md).

## The larger gain came from rejecting whole branches

Instead of enumerating every orbit assignment, the new search chooses mirrored
hex digits from the outside in. Those choices determine both an exact interval
for all completions and some low binary bits. A shared decimal prefix of the
interval endpoints fixes the required suffix of any decimal palindrome.
If its reversal disagrees with the fixed value modulo `2^k`, every completion
in that branch is impossible.

This rule uses exact arithmetic and a necessary condition. Decimal-boundary
ambiguity passes conservatively. The proof is in [VERIFICATION.md](VERIFICATION.md),
and the independent Python and native C implementations live in `experiments/`.

The Python reference accounted for all 187,650,018,028,196 assignments through
46 hex digits in about 28 seconds of traversal, visiting 20,785,408 nodes and
checking 8,695,032 leaves. Through 56 digits it accounted for
192,153,585,174,882,980 assignments in about 434 seconds. These are single
measurements on a shared machine, not asymptotic guarantees. Covered assignments
include whole rejected subtrees; they are not individually tested candidates.

The native C version preserves the same traversal and rejection decisions.
Cross-language checks compare every accounting field and hits, including the
entire completed Python range. Separate big-integer witnesses check native
decimal conversion through `2^256 - 1`.

An optional refinement considers small sets of decimal prefixes across interval
boundaries. It rejects more branches but was slower in the measured cases, so
the simpler common-prefix method stays the default. That negative result is
retained as a reproducible experiment rather than reported as a speedup.

## What this establishes

The completed ranges, incomplete groups, commands, and run budgets are explicit
in [RESULTS.md](RESULTS.md). Budget expiry never upgrades a partially searched
group into a bound. No nontrivial triple palindrome was found in the completed
searches recorded there.

The work gives a repaired GPU check and a much cheaper exact search. It does
not give a global nonexistence proof. A sound rejection rule for any length and
an enormous finite empty range still leave infinitely many lengths unsearched.
[ROADMAP.md](ROADMAP.md) records the remaining ideas and the limits of density
and fixed-modulus arguments.
