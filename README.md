# multibase-palindrome-search

A computational search for integers that are palindromes in base 2, base 10 and
base 16 at the same time, with the source code, the exact bounds reached, and an
account of how the results were checked. The point of publishing is to invite
scrutiny: if you can break the enumeration argument, find a bug, reproduce or
extend the search on other hardware, or make progress on a proof, please open an
issue.

## The question

Is there any integer greater than 9 whose digits read the same forwards and
backwards in binary, in decimal and in hexadecimal?

The single digits 0, 1, 3, 5, 7 and 9 qualify trivially: each is one digit in
decimal and hexadecimal and a palindrome in binary. Nothing else is known.

The question came up on The Rest Is Science, the Goalhanger podcast hosted
by Hannah Fry and Michael Stevens, in the episode
[Is 100 Better Than 101?](https://www.youtube.com/watch?v=mvUSeUl29d0), where
Stevens mentioned that nobody has found such a number, citing Rick Regan's
blog Exploring Binary. Hearing that on a quiet evening with an idle 16-core
machine is how this repository started: the first program was a brute-force
scan written to see whether 2^32 would be enough. It was not, and the rest
followed from there. Regan's article is
[In Search of Decimal/Binary/Hexadecimal Palindromes](https://www.exploringbinary.com/in-search-of-decimal-binary-hexadecimal-palindromes/)
from April 2010, which reports a search that found nothing and asks whether
existence can be proved either way.

## Result

No integer greater than 9 is a palindrome in bases 2, 10 and 16 within these
bounds:

| Subset by leading hex digit | Searched through | Equivalent upper bound |
|---|---|---|
| 1 or 3 | 64 hex digits | 2^256, about 1.2e77 |
| 5, 7, 9 or F | 46 hex digits | 2^184, about 2.5e55 |

Other leading digits cannot occur: even digits end in a zero bit, and B and D
fail the case analysis (see Method). Together the two rows cover every integer
below 2^184, and the first row alone covers its subset to 2^256.

Prior art: Regan's 2010 search covered the 1 or 3 subset through 64 hex digits
and the 5, 7, 9, F subset through 32 hex digits. This work confirms both bounds
independently with a different construction and extends the second from 32 to
46 hex digits: lengths 33 to 38 on a 16-core CPU, lengths 39 to 46 on one
RTX 4090. The new ground is about 1.9e14 candidates.

Timings, counts and the exact commands are in [docs/RESULTS.md](docs/RESULTS.md).

## Method

A linear scan is hopeless past 2^40, so the programs generate only numbers that
are already palindromic in both base 2 and base 16, then test base 10.

Two involutions act on bit positions of a number with L hex digits whose
leading digit has b significant bits (b from 1 to 4, so N = 4(L-1)+b bits):

- H, the hex palindrome condition, pairs nibble j with nibble L-1-j at the
  same bit offset.
- B, the binary palindrome condition, pairs bit q with bit N-1-q.

A number satisfies both conditions exactly when its bits are constant on the
orbits of the group generated by H and B, the padding bits above the leading
digit are zero, and the top bit is one. Union-find over at most 256 positions
computes the orbits, so each (L, b) pair yields a set of free orbit masks. The
search enumerates assignments of the free orbits by Gray code, flipping one mask
per step, and tests each candidate for a decimal palindrome.

The decimal test is a cheap prefilter followed by a full check. The prefilter
recovers the first three decimal digits from a double of the top 128 bits, with
an exact fallback whenever the estimate sits near a rounding boundary, and
compares them against the last three decimal digits, which are tracked
incrementally as a residue mod 1000. The prefilter can only err by passing a
candidate to the full check, never by rejecting a palindrome. About one
candidate in a thousand reaches the full check.

The leading-digit classification falls out of the orbit construction and agrees
with Regan's
[structural analysis](https://www.exploringbinary.com/the-structure-of-binary-hexadecimal-palindromes/):
b = 1 gives leading digit 1, b = 2 gives 3, b = 3 gives 5 or 7, b = 4 gives 9
or F.

Four programs are included, in the order they were written:

| Program | Approach | Range |
|---|---|---|
| `src/tripal.c` | linear scan of every integer, three palindrome checks | 64-bit values |
| `src/tripal_hex.c` | mirror hex halves to generate hex palindromes | 64-bit values |
| `src/tripal128.c` | orbit construction, 128-bit arithmetic | 128-bit values |
| `src/tripal_wide.c` | orbit construction, 256-bit limbs, incremental residue | 256-bit values |
| `src/tripal_cuda.cu` | the same construction on an NVIDIA GPU, two-stage device prefilter | 256-bit values |

The earlier programs are kept because they are independent implementations that
the later ones were checked against. None of the hot paths use strings.

The GPU version keeps one contiguous Gray-code slice per thread and tracks the
value mod 10^9 incrementally. Its first stage compares the first three decimal
digits, taken as a float from the top 32 bits, against the last three; its
second stage compares nine digits, taken as a double from the top 64 bits,
against the last nine. Survivors go to the host for the exact check. On an
RTX 4090 it covers the 128-bit range in 0.2 s, about 70 times the 16-core CPU.

## Verification

Each layer was checked against an independent implementation, and the chain is
written up with its remaining weak points in
[docs/VERIFICATION.md](docs/VERIFICATION.md). In brief: the orbit enumerator
agrees with the mirror-half generator and with a Python string-reversal
enumeration on every base 2 plus base 16 palindrome up to 20 hex digits (2.8
million numbers); the decimal routines agree with string reversal on random
numbers up to 77 digits; and a verify mode confirms the incremental residue
against a direct computation on every one of 2.86 billion candidates up to 30
hex digits while checking that the prefilter never rejects a candidate whose end
digits genuinely mirror.

The main weakness is that no positive control exists: there is no known
non-trivial hit to plant, so the pipeline has never been seen to find one.

## Quick start

Requires clang (tested with clang 22 on Windows 11; the code is plain C with
Windows and POSIX thread backends). The 128-bit and 256-bit programs use 128-bit
division helpers from compiler-rt, hence the extra flag.

```
sh build.sh         # builds bin/tripal, bin/tripal_hex, bin/tripal128, bin/tripal_wide
sh build.sh check   # self-tests, cross-program agreement, verify mode to 24 hex digits
make check          # same, for environments with make (untested here; mirrors build.sh)
build_cuda.bat      # Windows: builds bin\tripal_cuda.exe with nvcc, locating MSVC if needed
nvcc -O3 -arch=native -o bin/tripal_cuda src/tripal_cuda.cu    # elsewhere

bin/tripal_wide 1 32                 # all of 128 bits, about 15 s on 16 cores
bin/tripal_wide 39 39                # next unexplored hex length, about 23 min on 16 cores
bin/tripal_wide 39 64 32 12          # leading digits 1 and 3 only, through 64 hex digits
bin/tripal_wide pairs 1 6            # list every base 2 + base 16 palindrome up to 6 hex digits
bin/tripal_wide verify 1 28          # assert residue and prefilter consistency per candidate

bin/tripal_cuda 39 40                # GPU search, about 20 s per hex length at this size on a 4090
bin/tripal_cuda all 1 20             # every candidate, for comparison with tripal_wide pairs
bin/tripal_cuda stage1 1 30          # stage-1 survivors, classified on the host against exact digits
```

Each `done:` line reports hits, candidates visited and wall time. Candidates
visited must equal candidates planned in the header line; a mismatch means a
thread partition bug.

## How to challenge this

Useful attacks, roughly in order of value:

1. **Break the enumeration argument.** Exhibit a number palindromic in bases 2
   and 16 that the orbit construction does not generate, or show the padding or
   leading-bit handling is wrong for some (L, b).
2. **Break the prefilter.** Exhibit a decimal palindrome below 2^256 that
   `decimal_ends_match` in `src/tripal_wide.c` rejects.
3. **Reproduce on different hardware or a different compiler**, especially
   without `-march=native`, and report whether the counts and times match
   [docs/RESULTS.md](docs/RESULTS.md).
4. **Write an independent implementation** in another language and compare the
   `pairs` output for small hex lengths.
5. **Extend the bound** and send the `done:` line with your hardware.

## Where this could go

[docs/ROADMAP.md](docs/ROADMAP.md) covers the cost of pushing the search
further, a meet-in-the-middle idea that could change the exponent, and what a
non-existence proof would have to overcome. The short version: a heuristic
estimate puts the expected number of undiscovered solutions near 2^-38, so more
searching will almost certainly find nothing, and only a proof can settle it.
